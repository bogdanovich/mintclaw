# PDFI4 Source-Quoted Boolean Assertions

## Operator Decision And Scope

On 2026-10-17 the operator approved mapping an explicit natural-language statement to its corresponding
checkbox, with an exact quote, field/person checks and clarification when ambiguous. This narrowly extends
the literal-token-only contract. It does not allow generating text, inferring related legal/financial status,
deriving eligibility, copying another person, or approving output.

## Evidence And Boundary

The current private/native path accepts exact boolean tokens, not a direct statement. The final audit
checks assignment coherence but receives no original quote; it cannot independently verify the claim.
Do not weaken source accounting, add language-specific keyword rules, or equate a prompt with proof.

Extend only the private positive-proposal wire with an optional typed boolean assertion and one exact
current-utterance literal. Native code owns offered checkbox identity, exact token-aligned source span,
owner/route/source/schema/revision, cardinality, overlap, constraints, correction authority, atomicity and
replay. Other kinds/dispositions cannot use the exception. A native boolean token cannot be inverted.

For assertion-bearing windows, make one additional bounded private verification call for the same configured
policy/model alias, without tools/search/history. Check the quote against bounded field meanings/document
evidence and intended person. Require a complete partition into verified IDs and advisory findings. The
verifier may confirm/reject proposals but cannot change a value or invent an assignment. Missing, foreign,
duplicate, malformed, unavailable or over-budget verification fails closed. Ordinary literal-only windows
keep their one-call path. Add no retry loop; existing alias fallback and persisted extraction caps remain.

Reuse native boolean values and encrypted events/spans. Add no persisted shape, store, daemon, rule registry
or all-schema prompt. Omit the optional private digest member for old requests, preserving replay digests;
changing an assertion/value cannot replay as identical. Quotes/values stay excluded from public JSON.

## Validation And Exit

Reproduce rejection of the new private wire on the old decoder. Cover true/false, exact quote, non-checkbox/
disposition/cardinality/token-contradiction refusals, person ambiguity, verification partition/failure/privacy,
mixed facts, correction, restart/replay and public JSON exclusion. Preserve ordinary behavior and native
limits. Qualify unrelated and official large forms through the actual agent/artifact/channel after merged
deployment. This stacked protocol follow-up does not complete PDFI4.

### Exact Literal Formatting

A real configured-provider probe using only the public two-field unit fixture returned valid JSON with
two whitespace-padded literals, which the existing strict decoder correctly rejected. Explicitly require
nonempty, trimmed exact fragments in the private interpretation contract, including prose/output/correction
and prior-resolution quotes. The otherwise identical probe then returned two accepted proposals with no
padded literals. Keep the decoder and native occurrence/accounting checks unchanged; do not silently trim
model output. This is format evidence, not proof that an entire retained job or Telegram transaction passed.
