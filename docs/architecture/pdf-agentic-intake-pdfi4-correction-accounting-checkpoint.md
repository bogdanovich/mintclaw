## Chosen Foundation

committed pending input with a native invalid/conflicting finding for that same field, at its exact
observed reservation count. The current proposal must be natively accepted or acknowledged as a valid
positive value. Old spans cannot overlap accepted or scoped evidence. Malformed, stale, duplicate,
wrong-job and unoffered references fail atomically with the current apply.

Record immutable prior-input settlements on the current pass outcome. A separately admitted clarification
uses its own extraction reservation: bookkeeping must not require a new extraction reservation on the old
input. The reproduced 32-pass boundary otherwise permanently rejects a valid new clarification, even
though no further model call on the old input is needed. The old counter stays unchanged and direct old
extraction still stops at 32. Each settlement binds the old input, its observed pass count, field and exact
span. Only findings through that count settle; later findings remain independent.
Unapplied old reservations covered by that snapshot become stale even for an acknowledgement that
does not advance a field revision. Completed exact replay remains readable; newly reserved later
passes retain ordinary validation and their independent findings.

Publish current field events and both inputs' bookkeeping in the existing encrypted snapshot. Do not
mutate earlier outcomes, add a second store, reset a counter, increase limits or add provider calls. Erase
raw text only after the unchanged whole-utterance, finding and scope gates pass. The optional encrypted
outcome property requires the new reader; older strict readers fail closed. Keep a coherent backup and
do not binary-only roll back after such an outcome is written. Preserve new user data and use a forward
repair or an explicitly authorized state migration; never restore a whole profile over newer facts.

unrelated facts. Treating rejected data as prose is false. A second resolution journal duplicates native
ownership. Raising caps or replacing jobs bypasses the bounded contract. The chosen change reuses the
native journal and atomic apply, independently of output-only guidance and backend schema stability.

Carry the failing tool regression forward. Add native tests for exact fragment accounting, untouched
facts, invalid replacements, wrong fields/roles, overlap, multiple inputs, duplicate/stale references,
identity isolation, 31/32-pass bounds, atomic failure, restart and exact/changed replay. Verify private
encoder/decoder bounds and public JSON exclusion. Run targeted/full/race tests, formatter/lint and current
head CI/review/rocket before merged deployment. Real agent, large-form and Telegram qualification remain
mandatory. This implements the admitted correction criterion; it does not broaden the goal.

## Live Copy Diagnostic: Scalar Interpretation Contract

An isolated owner-authorized copy of the large-form state reproduced a private proposal with two literals
for one checkbox (`answer_conflict`) and another single non-boolean literal (`field_invalid`). No live
reservation was spent. Native rejection was correct: the private wire/prompt did not specify scalar
cardinality or expose the native boolean-token policy clearly enough.

Keep this repair in the same private-positive-proposal boundary: project native boolean literals from
the same table used by deterministic validation and include source maximum length. A scalar has one
canonical value, but redundant evidence such as two synonymous boolean tokens need not be discarded.
Permit multiple positive scalar literals only when every literal independently passes the unchanged
native normalizer and all normalized values are equal. A disagreement is a native conflict; an invalid
fragment is a native invalid finding. Account all unanimous fragments, but append one field event.
Multi-select lists retain their existing distinct-choice behavior; dispositions still require one exact
instruction. Do not concatenate/drop fragments, generate tokens, relax native types, add model retries,
or infer a new value. Invalid supplied values still reach ordinary native validation.

This adds a shared read-only policy projection, not another parser, model call or persisted shape. Validate
policy/normalizer equivalence, owned copies, unchanged invalid-token refusals, scalar unanimity/conflicts/multiselect,
and the existing intake suite. Requalify the bounded copy probe before spending the live large-form budget.

A field-level invalid/conflicting finding can cover a set containing both valid and invalid fragments.
Do not demand that every superseded fragment individually reproduce that finding: this would strand the
valid members of a rejected set. The existing native field-level finding, exact unaccepted source spans,
same-field current positive acceptance, protected semantic link, non-overlap and atomic revision/budget
gates remain the resolution proof. Interpretation of the link remains in the existing private call;
no claim that native code can prove a fragment's natural-language meaning is introduced.

## Review: Historical Accounting Is Not Current-Value Authority

A chained native regression shows that a settled rejected literal may be acknowledged as historical
accounting without matching the canonical value. That acknowledgement must never authorize another
settlement. Native selection now projects an ephemeral current-value ID subset, derived only from new
accepted events or the existing exact normalized-value/canonical-value comparison and correction gates.
Keep historical acknowledgement/replay semantics unchanged. Cross-input authorities must use this
native subset rather than treating every accounted fragment as a current positive decision. No model
flag, extra parser, value copy, new reservation or persisted property is introduced by this refinement.
