# PDFI4 Private Interpreter Checkpoint

This is a bounded stacked packet on the private-provider prerequisite #1492. Native proposal application #1495 is
merged. The execution-only clarification #1498 permits preparing this packet while prerequisite CI runs. Do not
enable the new dialogue or deploy this dependent behavior before its prerequisites merge and its own gates pass.

## Ownership And Alternatives

The existing configured document auditor already owns the resolved deliberative providers and explicitly declared
equivalent aliases. Reuse it for a direct, marked, tools-disabled interpretation call. A separate model router, secret
store or document planner would duplicate ownership and is excluded. Combining the interpreter and channel UI into
one large PR would obscure their privacy boundaries; a small adapter with no public UI activation is chosen.

The caller supplies one native reserved eight-field pass, optional current field states for corrections, and at most
two pages/4,000 characters of text evidence. The protected utterance and accounted literal spans stay ephemeral.
The native pass and ApplyFormIntakePass retain owner/route/source/schema/revision and assignment authority. The model
can only propose exact literal references, uncertainty findings and advisory dialogue intent. It cannot invent values,
write files, finish the transaction, approve output, or call tools.

## Privacy And Validation

Keep private request/response projections out of ordinary JSON. Explicit private wire DTOs are used only for the
ephemeral provider call. Reuse sensitive-request controls: nil tools, native_search=false, no ordinary cache lineage,
no agent hooks/history/trace path, and fixed non-echoing failures. Unknown aliases cannot create arbitrary providers.
Only caller-selected aliases already resolved from the document audit configuration can run; the later workflow
must follow the existing declared primary/equivalent order rather than a general cheaper-model fallback.

Request encoding and response decoding have fixed byte/count limits. Reject tools, markdown, trailing/unknown fields,
unknown or duplicated candidate IDs, invalid literal-reference shapes, and unsupported intents/finding codes. This
is structural validation, not semantic role proof or assignment acceptance. Native application still checks exact
literal provenance, types, conflicts, corrections and atomic accounting. Actual-model role/adversarial qualification
remains mandatory.

## Later Integration

Protected ingress must persist a non-clearable document-owned replay guard before native admission and avoid content
previews. The document workflow must retain uncertain text/findings in the existing pass outcome, accept multiple
messages, ask grouped targeted questions and preserve final review/confirmation. No adapter mock or first question
completes PDFI4. Scoped partial output, deployment, real Telegram/artifact qualification and exit remain required.
