# PDFI4 Bounded Clarification Window Priority

PDFI4 is not complete. This checkpoint does not establish the cause of the historical I-134 apply rejection.

## Invariant And Reproduction

Protected retry has a persisted 32-reservation budget. A large form may need almost that many eight-field views for
one traversal. The current bridge restarts the structural traversal on a new clarification/retry. It can spend the
remaining reservations on unrelated fields before reaching the native finding that the clarification addresses.
Raising/resetting limits, dropping the original input or starting another job would conceal this recovery defect.

Reproduce it with an unrelated large synthetic schema: one retained literal has an advisory finding in the last
window, and one reservation remains. A second protected message clarifies its role. The original must use its last
reservation on that finding, accept the same original literal once, and consume both messages. Restart and exact
replay must keep the original budget, ledger and cleared raw inputs. Unrelated traversal order is not authority.

## Bounded Change

Prioritize existing structural windows containing native findings, preserving their relative order and every
candidate/page bound. Then visit other windows in their original order if the input remains pending. No schema or
role-based heuristics, new planner, state, counter, reservation exemption, discarded input or semantic permission.
The private interpreter still sees only an existing bounded view. Native apply still validates every assignment,
literal, owner, revision and receipt. Current findings are already an authenticated value-free native projection.

Prefer this scheduling correction over larger budgets, another private round trip, or a new selector abstraction.
Keep missing/uncertain/outside-window facts protected and stop truthfully if the unchanged budget is exhausted.
Require the failing real bridge regression, replay/restart and existing budget/privacy suites, normal exact-head
CI/review/approval and merged deployment. Live artifacts and Telegram remain separate mandatory gates.
