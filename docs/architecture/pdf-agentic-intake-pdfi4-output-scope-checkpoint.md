# PDFI4 Native Output-Scope Checkpoint

This is an inactive prerequisite for [PDFI4](pdf-agentic-intake-pdfi4-goal.md), not production enablement or exit evidence.
The private interpretation, semantic applicability, deployed model/channel qualification and artifact oracles remain
required. The operator-approved flattened I-134 lane is unchanged; editable hybrid output is still deferred.

## Native Contract

One existing form job carries complete intent (the legacy default) or `editable_draft` and canonical exact deferred
field IDs. Deferral is scope, not a fabricated blank value. The source's `Required` flags and complete-mode validation
are unchanged. Only a currently unanswered field without a source value can be effectively deferred. Accepted,
preserved, conflicting or invalid values cannot disappear under this scope.

The native replacement API accepts at most the existing 256-field schema bound. Interpretation still uses eight-field
windows; accepting the validated whole omission set makes one atomic scope change possible without another batch
ledger or planner. It authenticates the owner/source/schema, refuses read-only and unknown identities, preserves exact
replay, and invalidates review/approval on a real scope change. Staged protected question claims fence the mutation.

Output capability comes from verified discovery eligibility, never field backend identity or an agency name. Legacy
jobs without capability remain complete-only and cannot acquire editable authority through start replay. A flattened
or unknown-capability job refuses draft scope without mutation or a write. The native audit sees explicit deferred
fields and may block them. Review binds the exact intent and omission set; final approval has a distinct draft policy.
Materialization omits deferred fields rather than clearing them. Artifact adoption also checks the proved output mode.
Draft review/delivery explicitly say that this is an editable incomplete draft; hybrid full output says print-ready.

## Compatibility And Rollback

Existing complete snapshots and approval shapes remain readable when optional scope/capability metadata is absent.
Older strict readers intentionally refuse the new persisted metadata; this is not a downgrade-compatible snapshot.
After any new-metadata job is created, retain an output-scope-capable reader for recovery, even if conversational intake
is disabled. Closing an intake mode alone does not remove the public job metadata. Do not restore an older binary
over such a snapshot or claim that an intake-only minimum reader can recover it. Restore a coherent pre-adoption
backup only with an operator-checked delivery/transaction reconciliation, not as a blind replay of completed writes.

## Evidence And Remaining Gates

Portable tests cover required deferral versus full refusal, accepted/source values, later values, invalid blockers,
audit refusal, stale authority, scope replay/change, staged claims, failed publication, restart, capability refusal,
pending protected value publication with commit/discard recovery, and output-policy/mode mismatches. These are native
and mocked semantic boundary tests, not proof of an emitted PDF,
real language extraction, Telegram ingress or production deployment. Those remain the next admitted work.
