## One Atomic Form Transaction

An optional private output instruction proposes complete filling or an editable draft, supported by one exact operator
utterance fragment. Dialog intent alone remains advisory. Bounded per-field `deferred` / `included` instructions change
scope, not the value ledger; they cannot manufacture blanks, correct values, or acquire approval authority. Only proved
editable AcroForm capability permits draft mode. Unknown and flattened capability refuse without consuming the input,
accepting facts, changing the job or substituting a flattened partial result.

Inside the existing authorized intake update, actual scope changes publish with accepted field events, source
accounting and exact replay outcome. They charge at most one scope revision per pass and invalidate old review and
approval. Both native entrypoints reuse the same scope mutation; existing owner/source/schema, pending-publication,
staged-claim, revision and capacity fences remain mandatory. A failure returns no acceptance or durable partial change.
Complete mode restores full validation. Source-required flags remain intact; provided, preserved, conflicting and
invalid values are not concealed by requested omissions. Later facts in a deferred field participate normally.

Exact scoped evidence survives every writable-schema view using the existing bounded outcomes, not another scan
cursor or planner. The private request carries only current capability/scope and deferred flags in its current field
window. Public projections count scope decisions separately from accepted values. The interpreter remains sensitive,
tools-disabled, bounded and no-cache; neither its utterance nor proposed literal enters ordinary JSON/history.

## Recovery And Qualification Boundary

An unavailable editable request has a value-free typed explanation and retains its job/input. Processing an older
pending error no longer prevents later admitted inputs from being examined, so an ordinary cancellation can reach the
existing bound control. Only the triggering receipt selects follow-up intent, and pending inputs still fence final
gates. Older clarification evidence is processed before its newer receipt; no second queue or control parser is added.

Nil output instructions preserve the exact legacy positive-fact digest shape. New scoped outcome metadata requires an
output-interpretation-capable reader while those intake records remain; existing output-capability metadata has its
separate minimum-reader requirement. Turning off composition does not downgrade stored snapshots.

Native and mocked private/tool tests cover multi-window restart/replay, mixed fact/scope publication and failure,
capability refusal, strict evidence, scope inclusion, later values, required/full validation, review/approval invalidation,
private bounded metadata and cancellation after refusal. They are not actual PDF, model-language or Telegram evidence.
Production composition and the admitted real-model/channel/artifact/privacy/recovery/deployment qualification remain.
