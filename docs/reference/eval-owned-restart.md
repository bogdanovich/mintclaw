# Owned Eval Restart Foundation

This internal prerequisite permits an eval supervisor to create one successor
for a gateway process it launched and admitted itself. It is not a public
restart command, an attach mode or the completed `general.history.restart`
scenario. Ordinary owned startup still requires a fresh prepared home.

## Authority And Identity

The owner retains the actual process handle, home/temp-directory file
identities, executable identity, admitted native probe and a preset fingerprint.
It also hashes the private native config/security inputs without retaining or
printing their contents. Failure to collect optional restart provenance does
not weaken or newly reject ordinary first-launch admission; it makes that
child ineligible for restart.

Restart requires the same private profile and executable, no widened tools,
no extra workspace inputs, native model metadata and an existing call budget.
The first process must stop and be reaped with native exit zero, no force and
no truncated log. A complete private-profile census and a known sealed native
budget receipt must pass before another process can start. Unsupported domains
or tool profiles are not borrowed for restart.

The owner refuses existing owner/PID state rather than deleting it. The old
native process removes its own ownership/PID markers during normal teardown.
It never adopts a process found by PID. A per-child atomic consumption guard
permits at most one successor attempt; failed or uncertain startup does not
make an old receipt reusable.

The successor uses a newly created generation directory beneath the verified
owned temp parent. Old scratch and evidence are not removed. A chain is bounded
to four generations, sufficient for a later fixed three-trial restart batch.
The same native admission loop binds the new probe to the newly created process
handle, not merely a matching listener. PID/instance identity must change;
source, config and home identity must remain stable.

## Budget Continuity

Every native child keeps its own nonce, receipt and process identity. Before
launching a successor, decode the previous receipt through the existing native
protocol and subtract its actual logical calls/reported tokens from the
remaining ceiling. Keep per-call input/output and concurrency limits unchanged.
Unknown usage, unclean shutdown, exhaustion or another stopped reason refuses
restart. This first foundation requires nonzero completed target work.

The launcher independently checks that the successor limits equal the derived
remaining limits. It does not accept a reset ceiling or invent an aggregate
native receipt. The previous native probe/lifecycle/budget/census are returned
for the later case's frozen evidence owner.

## Model-Free Validation

Unit controls use an explicitly labeled exited helper process and synthetic
native-protocol receipts to test identity/budget refusal. They are not claims
of native AgentLoop execution or live qualification.

A separate integration uses two real native CLI gateway processes and a local
synthetic HTTP provider. It sends a marker, waits for native terminal delivery,
restarts the owned process, reconnects with the same session identity and asks
for the marker without repeating it. The second provider request must contain
the restored history. Checks include decremented real budget receipts,
single-use predecessor authority, refusal of fresh-home admission after use,
four clean canonical messages, exactly two delivered native finals and final
clean shutdown. No paid models or production data are used.

## Remaining C3e Work

The versioned case/profile, transport reconnection at the conversation engine's
owned boundary, complete run-scoped generation/budget rollup, per-generation
native model correlation, frozen grading and bounded live qualification remain
separate work. This prerequisite alone cannot promote or pass the restart eval.
